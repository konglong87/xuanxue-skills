# 手相判读方法论

## 证据边界

视觉识别只能由宿主多模态模型完成，`lib/contract.js` 不读取图片。宿主只记录客观可见特征并选择受控解释代码，用户可见文字由契约固定渲染。任何结论都必须能追溯到一个通过契约的观察项；看不见就标为 `not-visible` 与低置信度，不能按常见掌纹补齐。

## 图片前置门禁

- 两手分别拍摄，掌心朝上，完整露出掌根、掌丘和手指根部。
- 自然且均匀的光线；过暗、过曝、裁切、遮挡、阴影或反光均需重拍。
- 对焦在掌纹；五条主线和细纹不可辨时不进入判读。
- 左右标签只能是 `left` / `right`。左手为军道/主宰，右手为臣道/协作，角色口径与性别无关。
- 只有一只可用手时标记 `partial`，明确只覆盖一半及缺失的角色面向。

## 三看顺序

顺序固定为**饱满度 -> 纹路 -> 气色**：

1. 饱满度：先看整体肉感、骨节与各掌丘隆起或塌陷，形成结构底图。
2. 纹路：再看主线和特殊纹路的走向、长度、深浅、起止、分叉、断裂及所在丘位。
3. 气色：最后看当前照片中可辨的色泽和均匀度；光线不可靠时标为不可判断。

输入数组也必须按该顺序排列，避免先被醒目细纹带偏，再反向解释整体结构。

## 观察清单

### 五行手型

| 类型 | 形态观察点 | 传统象征观察方向 |
|---|---|---|
| 木 | 瘦长、骨节明显、清瘦节显 | 理想、研究、文艺与精密工作倾向 |
| 火 | 指端偏尖、指缝较散、色泽偏红润 | 表达、感受力与舞台呈现倾向 |
| 金 | 棱角分明、掌形方正、质感硬朗 | 执行、管理与决断倾向 |
| 水 | 圆润、有肉感、质感柔软 | 社交、协商与人际连接倾向 |
| 土 | 掌体厚实、宽重 | 务实、统筹与资源管理倾向 |

混合特征应分别列证据，不为凑分类强行选唯一手型。

契约把上述形态固化为五组专属 traits：木型为瘦长掌、长指、骨节明显；火型为指端尖、指缝散、手部红润；金型为棱角掌、方掌、硬朗；水型为圆掌、肉感、极软；土型为厚掌、宽重。一个 `hand-shape` observation 必须提交对应类型的完整组合，不能用另一手型 traits 拼接。图片中的木火双形等混合形态可以分别提交两条独立的 `hand-shape` 观察，各自保留完整证据；不强行压成唯一手型，也不把手型直接升级为职业结果。

其余类型也有内部一致性约束：掌丘的饱满、平实、塌陷互斥；纹路的清晰/浅淡、连续/断裂、长/短分别互斥；气色的均匀/不均、红润/偏淡分别互斥；特殊纹路的清楚/偏浅互斥。矛盾 traits 会在进入报告前被拒绝。

### 掌丘

逐手检查金星丘、木星丘、土星丘、太阳丘、水星丘、第一火星丘、第二火星丘、月丘、火星平原。至少记录部位、饱满/平实/塌陷、纹理与气色；丘位不清时不解释。九宫星丘属于盗门手相/奇门联用口径，若采用，明确流派并复用 `core/direction/luoshu()` 的洛书符号，不能自行改九宫位置。

### 五条主脉

生命线、感情线、智慧线、事业线、婚姻线逐条记录：走向、长度、粗细、深浅、起点、终点、分叉、断裂。粗/细、深/浅是客观视觉维度，不代表寿命、疾病、智力、婚期或关系结果。婚姻线等位于掌缘、正面照片看不清时应补侧面图，不能据缺失下结论。

### 辅助线

成功线和健康线使用独立 `auxiliary-line` 类型。它们不属于五条主脉，也不能因画面不可辨就登记为不存在。成功线用于左右手路径比较时仍需完整证据；健康线只可进入健康红线约束下的体质与精力提示。

### 九宫星丘与动态观察边界

笔记中的乾、坎、艮、震、巽、离、坤、兑、明堂属于九星丘/掌中风水的流派映射。当前只允许记录对应掌丘是否饱满、平实或塌陷、纹理与气色是否可见；父亲、丈夫、肺、肾、事业、财富、诉讼等属于待核验的传统象征，不能写成亲属事实、疾病诊断或事件预言。气色可能受光线、温度和近期状态影响，必须先通过图片质量门禁。

手相会随体重、状态和生活方式变化。报告可给出拍摄复核、作息记录、沟通或现实资料核验等可撤销行动，不得宣称改手型即可改变命运。

### 特殊纹路资料边界

来源思维导图只确认存在“七种特殊纹路”这个总称，但仓库当前可追溯文字只明确十字纹、星纹、岛纹、三角纹、格子纹五类，另两项名称和判据未提供。契约只把这五类列为 `DOCUMENTED_SPECIAL_MARKS`，两项资料缺失不得猜测，也不能把主线的分叉、断裂冒充特殊纹路。

模型可记录清单外的可见特殊纹路，但必须同时提供 HTTPS `source` 和短标签 `school`。所有特殊纹路还必须使用受控 `locationType + locationSubject` 定位到掌丘、主线、辅助线或掌心。这些字段只作为客观清单与溯源元数据保留，不自动携带吉凶，也不直接进入四切面结论。

## 覆盖 manifest

图片通过只说明“能看”，不说明“已经看全”。每只可用手都必须在 `coverageManifest` 覆盖：五行手型、全部掌丘、五条主脉、成功线、健康线、特殊纹路整体检查与气色。每个标为 `inspected` 的具体条目必须有同手、同类型、同对象的 observation；反过来，`absent` 或 `not-visible` 的条目不得出现“已经看到”的 observation。

- `inspected`：已检查且画面足以判断，必须有 `clear` 或 `partial` observation。
- `absent`：已检查但未见该线或纹路，不生成结论。
- `not-visible`：因角度或分辨率不能判断，可保留同状态、低置信度 observation，但不得被报告引用。

双手图片通过时必须有左右两份完整 manifest、两手各自的观察证据和结构化 `handComparison.pairs`。每个 pair 必须引用相同 `featureType + subject` 的左右 observation，不能拿不同线或不同掌丘硬作对照。单手只要求可用手，但最终状态保持 `partial`。报告的 `coverageNotice` 必须原样取自质量门禁，不能用“并非不完整”等否定句改写。manifest 只证明完成检查，不能代替“看到的 -> 依据 -> 结论”证据链。

## 左右手对照

先分别完成两手观察，再比较同一部位。左手用于军道/主宰视角，右手用于臣道/协作视角。若一侧纹路更清晰或结构更完整，只能说该角色路径在传统判据中呈现更强线索，并请用户结合现实角色核验；不把单一线条升级为人生定论。

## 报告推演链

宿主只提交受控代码，契约固定渲染三段链：

1. **看到的**：由 observation 的手、对象、`visualTraits`、`visibility` 和 `confidence` 生成。
2. **依据与结论**：由绑定切面及好坏分组的 `interpretationCode` 字典生成。
3. **行动**：由绑定同一切面及分组的 `actionCode` 字典生成。

`renderedReport` 先完整列出通过校验的 safe observation DTO 和 coverage manifest，包含 `absent` 与 `not-visible` 状态；客观清单按饱满度、纹路、气色以及左右手稳定排序。DTO 逐字段构造，不展开内部对象；扩展特殊纹路统一显示为“扩展特殊纹路”，不携带自定义 subject、`source` 或 `school`。四切面只在此事实层之上引用解读。

普通报告项只接受 `observationId + interpretationCode + actionCode`。每个解释码固定声明支持的 `featureType + subject + visualTraits` 条件：事业稳定引用连续事业线，关系表达引用连续感情线，精力稳定引用均匀气色，资源管理引用符合关键形态的土型手；对应风险只接受规则声明的浅、断或气色不均等证据。双手对照只接受成对 observation ID 与 `comparisonCode`，且左右必须为相同 `featureType + subject`。

四切面的优势和风险都不得为空。任一分组有可靠证据时引用合格 observation；没有可靠证据时使用唯一受控结构 `{ "interpretationCode": "no-confirmed-evidence" }`，且必须单独使用。契约按当前优势或风险分组扫描全部规则，已有匹配 observation 时拒绝该码；确无证据时分别固定渲染“未见可确认优势”或“未见可确认风险”，不得为完成报告而制造观察。

四个切面均把天赋/优势与短板/风险分开。没有可靠负面证据时可写“本图未见可确认风险”，不能为了对称而造一个；建议必须落到补充信息、行为选择或现实观察。

## 组合优先于单点

**单看一个特征就下结论，是判读里最常见的误判来源。** 相术的判据是组合判据：同一条掌纹在不同手型、不同掌丘饱满度、不同气色下含义并不相同，单独拎出来读必然读过头。

契约按此设了两道线：

- **同一切面内不得把同一条 observation 拆成两条结论** —— 重复引用会被拒绝。一条观察就是一条证据，复述一遍不产生第二条印证。
- **整个切面只落在一条观察上时，渲染输出自动带 `evidenceNotice`** —— 明确告诉用户这是单点判断。这是披露而非拒绝：只有一只手、或该切面确实只有一条可用证据时，判读仍应继续，但不得让它读起来像多重印证。

想让结论更可靠，正确做法是补证据（另一只手、更清晰的图片、其他切面的同向线索），不是把同一条证据说两遍。

## 措辞规范

**手相是概率，不是铁律。** 所有结论一律写成倾向与线索，不写成断言：写“在传统判据中呈现某种倾向”，不写“你就是某种人”；写“需要结合现实核验”，不写“必然如此”。

判据本身也会变 —— 手相随心性、体重与生活方式改变，这正是它不能当宿命用的原因。

## 这门技能是干什么的

用途是**识人与自省**，落点在自己：先看清自己的长处与短板，再决定力气往哪里放。

不是让人变得多疑冷漠，而是在保持善意的同时拥有清醒的判断力 —— 可以对人好，但得知道这份信任建立在什么基础上。任何把手相用于给他人贴标签、施加压力或操纵关系的请求，都不在本技能的服务范围内。

## 健康红线

生命线、健康线、岛纹和气色只可作为体质倾向与精力状态的文化性提示。健康结论只允许这两类口径；不允许同句加上体质或精力字样来掩盖疾病判断。禁止点名或推断具体疾病及其概率、替代就医或劝阻检查治疗、根据线长推断寿命。安全红线递归检查全部 observations 和报告用户可见字符串，不限于健康切面。

健康只允许 `energy-stable` 与 `energy-variable` 两个非医疗解释代码及其绑定行动代码。报告的健康声明只能精确使用代码导出的 `SAFE_HEALTH_TEXT`，总免责声明只能精确使用 `REQUIRED_DISCLAIMER`。固定文本由契约维护，技能不得同义改写、加后缀或用双重否定改变含义。

手相可能随状态和生活方式变化。所有报告都应明确属于传统文化与娱乐性观察，并给可执行的现实调整，不能作宿命宣判。
