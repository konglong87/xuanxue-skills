`core/calendar/__tests__/fixtures/dayun-crosscheck.json` 的黄金值**不来自本仓库**，来自两个独立实现：

| 来源 | 性质 | 覆盖 |
|---|---|---|
| **BaziGo** | 独立 Go 仓库（`qiyun.go` / `dayun.go`） | 顺逆、起运公历、大运干支、起运周岁 |
| **独立实现** | 按古法口诀另写一份，不参考 `core/calendar/cycles.js` | 顺逆、起运折算、大运干支 |

**两者完全一致的项才入库。** 本仓库对照的是它们，不是自己上一次的输出 —— 这是它区别于 `cycles.test.js` 里那些回归断言的地方。

fixture 已入库，重新生成或扩充时按下面走。

## 一、BaziGo 侧

BaziGo 是独立 Go 仓库，本仓库不引入 Go 运行时依赖，也不修改它。在仓库外新建临时 module：

```
module bazigooracle
go 1.16
require github.com/warrially/BaziGo v0.0.0
require github.com/yangtizi/htmlgo v1.0.0
replace github.com/warrially/BaziGo => /path/to/BaziGo
```

把 BaziGo 的 `go.sum` 原样复制过去，`GOPROXY=off go build` 离线构建。入口取：

```go
b := bazi.GetBazi(y, mo, d, h, mi, 0, sex) // sex: 1 男 0 女
b.DaYun().ShunNi()            // 顺逆
b.DaYun().Zhu(i).GanZhi()     // 第 i 步大运干支
b.DaYun().Age(i)              // 第 i 步起运周岁
b.QiYunDate()                 // 起运公历
```

## 二、独立实现侧

按口诀重算，**不看 `cycles.js`**：

- 阳年男 / 阴年女顺行，从出生时刻顺数到**下一个节**
- 阴年男 / 阳年女逆行，从**上一个节**逆数到出生时刻
- 3 天 = 1 年，1 天 = 4 个月，1 个时辰(2 小时) = 10 天，1 小时 = 5 天
- 大运干支以月柱为基准，顺行取月柱后一位起排，逆行取前一位

节气时刻可以取本仓库的 `core/calendar/jieqi` —— 该层已由 59 条 BaziGo 四柱黄金用例间接交叉验证，独立的是**顺逆判定 + 折算 + 大运排列**这三段算术。

## 三、取样

Steve Jobs（1955-02-24 18:51:28 真太阳时，阴年男命逆排）+ 每年抽两个节，各取「节前 2 小时」「节后 2 小时」「节后 5 天」，男女各一份。必须覆盖阴阳年 × 男女**四个象限**，测试会校验这一点。

## 四、已表征的口径差异（不是缺陷，不许抹平）

**起运日期算法有两派，本仓库属于「日历加法派」：**

| 派别 | 做法 | 代表 |
|---|---|---|
| 日历加法 | 折算出「N 年 M 月 D 日」后按**真实历年历月**加到出生时刻上 | 本仓库、独立实现 |
| 定长缩放 | 把距节秒差**乘以 120** 加到出生时间戳上（等价 1 年 = 360 天） | BaziGo |

两派在**顺逆与大运干支上完全一致**，只在起运日期上分歧：定长缩放每 1 年起运岁数少算约 5.25 天，起运 10 年就少约 52 天。起运日期跨过元旦时，首运年份差一年，连带全部大运的起始虚岁整体差 1 岁。

抽样 504 例中约 9.5% 落在这个区间。测试对此的处理是**表征而非容忍**：允许且只允许「整体差 1 岁」，且必须能由「本仓库起运公历年 = BaziGo 起运公历年 + 1」解释；出现任何其他差异即失败。

**发现新差异时先归因再定归属**：属本仓库缺陷就修代码，属口径差异就在本文档记录成因。**不得为了让测试变绿而直接抄任一外部实现的值。**
